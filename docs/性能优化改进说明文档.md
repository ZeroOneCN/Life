## 二、代码重构建议

### 2.1 短期重构（1-2 周）

| 项 | 内容 | 预期收益 | 工作量 |
|----|------|---------|--------|
| 引入 ESLint + Prettier | 配置代码规范，自动格式化 | 代码风格一致性提升 | 0.5周 |
| 补充 JSDoc 注释 | 对核心函数补充完整注释 | 可维护性提升 | 0.5-1周 |

| 数据库索引优化 | 慢查询分析 + 索引优化 | 查询性能提升 | 1周 |

**总计：** 3.5-4.5 周

### 2.3 长期重构（持续）

| 项 | 内容 | 预期收益 | 工作量 |
|----|------|---------|--------|
| 共享逻辑抽象 | 提取通用 CRUD、分页、筛选逻辑 | 代码复用率提升 | 持续 |

| API 文档 | 引入 Swagger/OpenAPI | API 对接效率提升 | 1-2周 |

## 三、测试体系建设

### 3.1 测试分层方案

| 测试类型 | 工具 | 覆盖目标 | 工作量 |
|----------|------|---------|--------|
| 单元测试 | Vitest（前端）+ Jest（后端） | 工具函数、纯函数、核心算法 | 2-3周搭建 + 持续补充 |
| 集成测试 | Supertest（后端） | API 接口测试 | 1-2周搭建 + 持续补充 |
| 组件测试 | Vitest + Testing Library | 核心 UI 组件 | 1-2周搭建 + 持续补充 |
| E2E 测试 | Playwright / Cypress | 核心业务流程 | 2-3周搭建 + 持续补充 |

### 3.2 实施建议

**第一阶段（1-2 周）：**
- 引入 Vitest（前端）和 Jest（后端）
- 配置测试环境和基础工具
- 编写工具函数的单元测试
- 目标：测试覆盖率达到 20%

**第二阶段（2-3 周）：**
- 引入 Supertest 做 API 集成测试
- 核心模块（认证、通知、健康）API 测试
- 目标：测试覆盖率达到 40%

**第三阶段（持续）：**
- 引入 E2E 测试
- 新功能必须有测试
- 逐步补充历史代码测试
- 目标：测试覆盖率达到 60%+

## 四、CI/CD 建设

### 4.1 当前状态

- ❌ 无自动化构建
- ❌ 无自动化测试
- ❌ 无自动化部署
- ❌ 无代码质量检查

*代码扫描验证：* ✅ 确认：无 .github/workflows 目录，无 CI/CD 配置文件

### 4.2 CI/CD 方案（GitHub Actions）

**流水线设计：**

```
代码推送 → Lint 检查 → 类型检查 → 单元测试 → 构建 → 部署
```

**具体步骤：**

| 阶段 | 内容 | 触发条件 | 耗时估算 |
|------|------|----------|---------|
| Lint | ESLint 检查 | 每次 push / PR | 1-2 分钟 |
| Type Check | tsc --noEmit | 每次 push / PR | 2-3 分钟 |
| Test | 单元测试 + 覆盖率 | 每次 push / PR | 3-5 分钟 |
| Build | 前端 + 后端构建 | main 分支 / tag | 3-5 分钟 |
| Deploy | 部署到服务器 | tag 发布 | 2-5 分钟 |

**开发量估算：** 1-1.5 周
- CI 流水线配置：0.5-1 周
- 部署脚本编写：0.5 周

**价值评估：** 高
- 代码质量有保障
- 发布效率提升
- 减少人为错误

## 五、扫描验证总结

### 已确认存在的问题（12 项）

1. ❌ 缺少测试覆盖 - 无任何测试框架和用例
2. ❌ 缺少 ESLint / Prettier - 无代码规范工具
3. ❌ 前后端类型不同步 - 独立维护
4. ❌ 缺少 API 文档 - 无 Swagger/OpenAPI
5. ❌ 无全局状态管理 - 仅 Context + useState
6. ❌ 后端 Router 过重 - 财务 router 普遍 500-800 行
7. ❌ 数据库迁移文件少 - 仅 1 个迁移文件
8. ❌ 缺少速率限制 - 无 rate limit
9. ❌ 密码加密库冗余 - bcrypt + argon2 并存
10. ❌ 缺少审计日志 - 无 AuditLog 相关代码
11. ❌ 无 React Query / SWR - 无服务端状态管理
12. ❌ 无 CI/CD - 无 GitHub Actions 配置

### 待深入验证的问题（6 项）

1. ⚠️ 业务逻辑重复程度 - 需逐模块对比

3. ⚠️ Magic Number 数量 - 需全局搜索统计
4. ⚠️ HTTP 请求日志 - 需确认是否有中间件
5. ⚠️ XSS 防护 - 需评估 helmet 配置和模板渲染
6. ⚠️ CSRF 防护 - 需确认是否有防护措施
7. ⚠️ Zod 输入校验覆盖度 - 需逐接口检查
